Messages with attachments no longer get stuck at "Sending…". A message whose attachments the browser could not keep in its attachment store is now sent with them, instead of holding up every message after it. When this browser no longer has a queued message's attachments, for example after its site data was cleared, the message is not sent as text alone. PI WEB first asks the machine whether it already has the message: if the agent has it, it stays sent and nothing comes back; otherwise its words go back to the composer, which says it was not sent and to send it again with the files. The messages after it go on. While the attachments only can't be read for a moment, the app row says so. Switching sessions or typing on while a large attachment is being saved no longer leaves the sent message in the composer to be sent twice, and pressing Enter again during that save sends the new words once it is done. Taking a message back now restores its attachments from the message in the transcript when this browser's copy can't be read. A draft or a take-back the browser refuses to store now says so. Attachments of messages that have left this browser are removed soon after, instead of being kept for at least 30 days.
