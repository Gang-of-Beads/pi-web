Run PI WEB in a single container without a service manager. `pi-web run` starts the session daemon, waits until it is ready, then starts the web/API server, and stays in the foreground: a stop signal drains the sessions, a web/API server that exits is started again while sessions keep running, and a session daemon that exits ends the run with a non-zero status. On Linux without a running systemd, `pi-web install`, `start`, `stop`, `restart`, `status` and `logs` now say how to run PI WEB instead of failing on `systemctl`, the Updates page no longer offers a restart or an update it cannot perform, and under `pi-web run` it says on the page to update the image or package and restart the container or the `pi-web run` process; on Windows it says how to update there. `pi-web doctor` there checks the data, config and agent directories, the session daemon's socket, PID 1 and the bind address instead of a service plan. A missing terminal module (`node-pty`) no longer stops the session daemon: terminals say they are unavailable while sessions keep working, `node-pty` is an optional dependency so a failed native build no longer fails the whole npm install, and doctor warns instead of failing and names the build tools it needs. An npm update whose `node-pty` build fails therefore completes too, and PI WEB restarts without terminals until the build tools are installed and PI WEB is reinstalled. See "Run in a container" in docs/install.md. Restart the session daemon to apply the terminal change.
