Stop a session daemon in one container from taking over a data directory that a running daemon in another container still uses. The owner now records its host and PID namespace and refreshes a heartbeat every 10 seconds; a daemon in another container that finds a live owner exits with an error naming that host, and takes over only after the heartbeat has stopped for 30 seconds. A clean stop still lets the next container start at once, and a daemon on an ordinary Linux, macOS or Windows host or in a WSL distro starts as before. Linux systems that run in their own PID namespace, such as ChromeOS Linux, LXC, Incus, Proxmox and NixOS containers, and Flatpak or firejail sandboxes, are treated as containers: they wait about 1 second at every start and about 30 seconds after an unclean stop. A daemon that finds another daemon recorded as the owner stops serving at its next heartbeat and exits with an error naming it, so hosts that share or sync one data directory now refuse to start or stop each other; never sync a data directory between hosts. The bundled Docker setup now gives the session daemon 70 seconds to stop, enough for its shutdown drain. Restart the session daemon to apply the ownership changes; for the bundled Docker setup, run `pi-web-docker update`, which also applies the longer stop time.
