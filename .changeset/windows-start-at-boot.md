PI WEB can start at boot on Windows, whether or not anyone is signed in: `pi-web install --at-boot`, run from an administrator account in PowerShell opened as administrator, registers the two scheduled tasks to start when Windows starts, as your account without a stored password, the Windows counterpart of `loginctl enable-linger` on Linux. The tasks, and PI WEB's terminals and agents, then run with your full administrator rights, because Windows does not limit tasks that run without a sign-in; the install and `pi-web status` say so. Any program running as your account, even in an ordinary window, can then use PI WEB's tasks and files to get these rights without a UAC prompt; use `--at-boot` only where that is acceptable. `pi-web stop`, `start`, `restart`, `uninstall` and `install` then need PowerShell opened as administrator and refuse in an ordinary window before changing anything; restarts from the Updates page or a PI WEB terminal, and uninstalls from a PI WEB terminal, keep working. The install checks that PowerShell is elevated and that your account can log on as a batch job before it changes anything, and a later `pi-web install` keeps the mode; `pi-web install --at-log-on` goes back to starting at sign-in, and either switch is refused inside PI WEB. Under the default mode, `pi-web install` now says at once when nobody is signed in to Windows, where it used to wait for a probe to time out.
